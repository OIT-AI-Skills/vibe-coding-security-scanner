# Vibe-Coded Application Security Review — Entrypoint & Orchestrator

## Purpose

This skill guides a structured security review of applications primarily generated by AI
tools ("vibe-coded"), where human review may be minimal. It is language-agnostic and
dispatches to specialized audit skills and language-specific extension rules.

## Operational Mode

**Do not ask clarifying questions.** Operate autonomously: state your assumptions
explicitly in the report header, proceed with the review, and note any limitations in
the Review Completeness section. This ensures the skill functions identically in both
interactive (VS Code agent) and non-interactive (CI/CD pipeline) contexts.

---

## Step 1 — Codebase Fingerprinting

Before any security analysis, perform the following:

### 1a. Detect the Tech Stack

| Signal File | Detected Stack |
|---|---|
| `Gemfile` / `Gemfile.lock` | Ruby; check for `rails` gem → Rails |
| `requirements.txt`, `pyproject.toml`, `setup.py`, `uv.lock` | Python; check for Flask, FastAPI, Django, etc. |
| `package.json` | Node.js / TypeScript; check for Express, Next.js, etc. |
| `go.mod` | Go |
| `pom.xml` / `build.gradle` | Java / Kotlin |
| `*.csproj` / `*.sln` | .NET / C# |

State the detected stack explicitly in the report header.

### 1b. Assess Codebase Size

- **Small** (< 50 application files, estimated < 5,000 LOC): Perform a comprehensive
  review of all files.
- **Large** (≥ 50 application files or estimated ≥ 5,000 LOC): Use **triage-first mode**
  — review files in the priority order defined in Step 2. Note unreviewed files.

State the chosen review mode in the report header.

### 1c. Identify Entry Points (Always Reviewed First)

Regardless of codebase size, always locate:
- Route / URL mapping files (`routes.rb`, `urls.py`, `app.py`, `router.go`, `Program.cs`)
- Controllers, views, and API handler files
- Middleware, especially auth and session handling
- Background job / async worker definitions
- Application configuration files (`config/`, `*.env`, `settings.py`, `*.yml`, `*.toml`)

---

## Step 2 — Review Priority Order (Triage-First Mode)

When in triage-first mode, review files in this order. Stop when context limits are
reached and note all unreviewed files.

1. Route definitions and URL maps
2. Controllers / API endpoint handlers
3. Models / ORM definitions
4. Service layer / business logic
5. Background jobs and async workers
6. Middleware (auth, logging, error handling)
7. Serializers, schemas, and API response formatters
8. Utilities and helpers
9. Configuration and initializer files

---

## Step 3 — Apply Specialized Audit Skills

After fingerprinting, apply these skills in sequence. For each one, either load it
explicitly via `#file:` in VS Code or reference the skill file path in your pipeline
invocation.

1. **`vibe-security-data-exfiltration`** — All paths through which data leaves the
   application boundary
2. **`vibe-security-secrets-audit`** — How secrets and sensitive configuration values
   are stored, transmitted, and accessed
3. **`vibe-security-privilege-escalation`** — Paths for privilege escalation, assuming
   AuthN/AuthZ is handled upstream

Additionally, apply **`vibe-security-language-extensions`** for rules specific to the
detected stack.

## Severity Reference

| Level | Definition |
|---|---|
| **Critical** | Directly exploitable with no special conditions; likely results in data breach, account takeover, or RCE. |
| **High** | Exploitable under reasonably common conditions; significant impact to confidentiality, integrity, or availability. |
| **Medium** | Risk requires specific conditions (user interaction, specific configuration, chained vulnerabilities). |
| **Low** | Defense-in-depth concern; minor risk or difficult to exploit in practice. |
| **Info** | Best-practice deviation; not a direct vulnerability. |

---

## Critical Constraints

- **Do NOT re-report findings that Brakeman (Ruby/Rails) or Bandit (Python) would detect**
  in their standard configurations. These tools are assumed to be running in the pipeline.
  Focus on what they miss: logic-level access control, architectural data flows,
  cross-component issues, and contextual business logic flaws.

- **For languages other than Ruby/Rails and Python**, apply a more comprehensive
  enumeration including issues that SAST tools would typically catch, since equivalent
  tools are not assumed to be in the pipeline.

- If uncertain whether Brakeman/Bandit would catch a specific issue, include it with the
  note: `[Verify: Brakeman/Bandit may detect this — confirm pipeline configuration.]`
